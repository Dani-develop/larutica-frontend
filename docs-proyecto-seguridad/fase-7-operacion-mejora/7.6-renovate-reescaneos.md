- Se añadió `renovate.json` con zona horaria `America/Costa_Rica`, ejecución semanal los lunes antes de las 06:00, máximo de un PR simultáneo, Dependency Dashboard y etiquetas `dependencies` y `security`.
- Las actualizaciones major requieren aprobación desde Dependency Dashboard.
- Se validó localmente que `renovate.json` es JSON válido.
- No se añadió ni modificó un workflow de OSV-Scanner: no existe actualmente y su implementación queda pendiente del ítem 3.2. Tampoco se creó un análisis alternativo ni se duplicaron checks.

### Cómo reproducirlo

1. Validar que el archivo es JSON válido desde la raíz del repositorio:

   ```sh
   node -e "JSON.parse(require('node:fs').readFileSync('renovate.json', 'utf8')); console.log('renovate.json válido')"
   ```

2. El propietario del repositorio debe habilitar e instalar Renovate como GitHub App para este repositorio. Después de habilitarla, Renovate leerá esta configuración y ejecutará su horario semanal; la primera ejecución y cualquier PR deben verificarse en el repositorio.
3. Cuando exista el workflow de OSV-Scanner del ítem 3.2, añadirle el horario y `workflow_dispatch` sin duplicar su análisis ni cambiar sus checks. Hoy no hay un workflow que se pueda ejecutar o probar.

## Decisiones tomadas

- Se usa Renovate GitHub App, no un workflow de Actions, para evitar gestionar tokens o secretos de Renovate en el repositorio.
- El horario es semanal y se expresa en la zona horaria de Costa Rica. Se limita la concurrencia a un PR y se usa Dependency Dashboard para aprobar actualizaciones major.
- El escaneo de imagen por digest se descarta porque el proyecto no tiene Dockerfile ni imagen propia.
- El reescaneo programado de dependencias no se implementa en este cambio: depende del workflow de OSV-Scanner del ítem 3.2, que aún no existe.
