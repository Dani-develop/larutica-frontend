# Evidencia 4.7 — Plan DAST con ZAP

## Artefactos

- Plan: `.zap/larutica.yaml`
- Workflow: `.github/workflows/zap.yml`
- Validación del objetivo: `scripts/validate-zap-target.mjs`

## Condiciones de ejecución

El workflow se ejecuta manualmente con `workflow_dispatch` y requiere:

- URL de un candidato aislado.
- Cuenta ficticia de prueba en `ZAP_USER` y `ZAP_PASSWORD`.
- Permiso para ejecutar análisis activo contra ese candidato.
- Exclusión de producción, Supabase, OnvoPAY y mapas externos.

El validador rechaza dominios de producción, `*.supabase.co` y hosts de Onvo. El plan cubre
rutas públicas y autenticadas, usa autenticación basada en navegador y cookies, espera el análisis
pasivo, ejecuta un análisis activo acotado y guarda un reporte HTML como artefacto.

## Estado

Plan y workflow versionados. La ejecución queda pendiente de contar con el ambiente y la cuenta
de prueba aislados. Una ejecución sin objetivo permitido o sin sesión válida se debe reportar como
incompleta, no aprobada.
