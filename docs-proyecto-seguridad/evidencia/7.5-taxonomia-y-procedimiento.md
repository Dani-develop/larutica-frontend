# Evidencia 7.5 — Registro único de hallazgos

## Decisión

El registro operativo es GitHub Issues del repositorio `Dani-develop/larutica-frontend`.
Issues está habilitado y `H-01` ya fue creado conservando su identificador. El archivo
[registro-hallazgos.md](registro-hallazgos.md) mantiene la trazabilidad local y no sustituye
al Issue.

## Taxonomía

| Campo | Valores o formato |
|---|---|
| Identificador | `H-NN` para hallazgos, `E-NN` para excepciones |
| Origen | `IA`, `ZAP`, `CI`, `prueba`, `revisión manual` |
| Estado | `Pendiente de investigación`, `Confirmado`, `Falso positivo`, `En corrección`, `Corregido`, `Verificado`, `Cerrado` |
| Severidad | `Crítica`, `Alta`, `Media`, `Baja`, `Informativa` |
| Tratamiento | `Corregir`, `Mitigar`, `Aceptar temporalmente`, `Investigar`, `Descartar` |
| Relaciones | amenazas `T-NN`, excepciones `E-NN`, PR y prueba de verificación |

## Procedimiento

1. Crear un Issue con la plantilla y asignar el siguiente `H-NN`.
2. Registrar versión/commit, origen, ruta o componente, evidencia y condiciones de fallo.
3. Justificar la severidad con impacto en confidencialidad, integridad o disponibilidad.
4. Clasificar explícitamente el resultado como confirmado, falso positivo o pendiente.
5. Enlazar las amenazas `T-NN` y excepciones `E-NN`; no copiar su contenido.
6. Enlazar el PR correctivo y la prueba que comprueba la corrección.
7. Cambiar a `Verificado` solo después de una ejecución reproducible.
8. Cerrar únicamente con decisión humana y evidencia de verificación.

No se registran secretos, tokens, contraseñas, cookies ni datos personales reales.
