### Ruleset a activar (configuración documentada)

El repositorio `Dani-develop/larutica-frontend` ya tiene el ruleset «Larutica · PR, revisión y CI» (id 27221926, consultado con `gh api repos/Dani-develop/larutica-frontend/rulesets` el 2026-11-13). Está en `enforcement: disabled` y `current_user_can_bypass: never`. Su contenido es el que se debe activar:

| Aspecto | Configuración |
|---|---|
| Ramas objetivo | `refs/heads/main`, `refs/heads/development` |
| Borrado de la rama | Bloqueado (`deletion`) |
| Push forzado | Bloqueado (`non_fast_forward`) |
| PR obligatorio | Sí (`pull_request`) |
| Aprobaciones requeridas | 1 (de otra persona; con `require_last_push_approval`, el autor del último push no puede ser quien aprueba) |
| Revisión de CODEOWNERS | Sí (`require_code_owner_review: true`) |
| Descartar aprobaciones al hacer push | Sí (`dismiss_stale_reviews_on_push: true`) |
| Rama al día antes de fusionar | Sí (`strict_required_status_checks_policy: true`) |
| Checks obligatorios | `Node 24 / ubuntu-latest`, `Node 24 / windows-latest`, `E2E flujos críticos` (app de GitHub Actions, integration id 15368) |
| Bypass | Ninguno para el usuario consultado; el propietario debe revisar la lista de bypass al activarlo |

Los nombres de los checks deben coincidir exactamente con los jobs de [`validate.yml`](../../.github/workflows/validate.yml): `Node 24 / ${{ matrix.os }}` (matriz `ubuntu-latest` y `windows-latest`) y `E2E flujos críticos`. Cambiar el `name:` de un job sin actualizar el ruleset deja el check obligatorio en espera permanente.

Pasos para activarlo (propietario del repositorio):

1. **Settings → Rules → Rulesets → Larutica · PR, revisión y CI → Enforcement status: Active.**
2. Confirmar que **Bypass list** está vacía.
3. Abrir un PR de prueba hacia `development` sin aprobación y comprobar que el botón de fusión está bloqueado (guardar captura: botón bloqueado, lista de checks y mensaje de revisión requerida).
4. Registrar aquí la captura o el enlace al PR bloqueado, con fecha y commit.

Estado: **pendiente de activación.** No hay captura ni PR bloqueado, y no se marcan como cumplidos los requisitos que dependen de la activación.
