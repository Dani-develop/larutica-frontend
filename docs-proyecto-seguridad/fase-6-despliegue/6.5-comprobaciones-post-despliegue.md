## Notas del proyecto

- Ambiente existente: Vercel (`vercel.json`, `docs/despliegue-vercel.md`). El ítem 6.2 permite documentar otra plataforma compatible.
- `npm run test:vercel` usa `LARUTICA_TEST_URL` y ejecuta el recorrido público de navegación definido en `tests/vercel/navigation.spec.ts`. Es de solo lectura y no crea cuentas, reservas, correos ni pagos.
- La URL de Preview puede apuntar a la misma base de Supabase que otros ambientes; no ejecutar contra ella pruebas que muten datos reales.

## Qué se hizo

- Se creó `.github/workflows/post-deploy-check.yml`, ejecutable manualmente con `workflow_dispatch` y los inputs requeridos `target_url` (HTTPS con host `larutica-cr.vercel.app`) y `deployed_commit` (SHA o versión desplegada).
- El workflow valida los inputs, ejecuta `curl` contra la URL indicada y guarda URL, fecha UTC, commit indicado, estado HTTP y cuerpo de respuesta como evidencia.
- Después ejecuta `npm ci`, instala Chromium y corre `npm run test:vercel` con `LARUTICA_TEST_URL` apuntando al despliegue. Publica los artefactos de health y smoke incluso si falla una comprobación. El workflow falla si cualquiera de las comprobaciones obligatorias falla o queda incompleta: validación de inputs, health check, `npm ci`, instalación de Chromium o smoke test.
- Para ejecutarlo: abrir **Actions → Comprobaciones post-despliegue → Run workflow**, ingresar `https://larutica-cr.vercel.app` y el SHA o versión desplegada que se valida. `deployed_commit` es declarado por quien inicia el workflow y debe coincidir con el registro del despliegue en Vercel antes de marcarlo como satisfactorio; el workflow no lo verifica automáticamente contra Vercel. Asociar el artefacto de la ejecución con ambos valores.
- El smoke test es público y de solo lectura. E2E del ítem 4.4, autorización y ZAP dependen de los ítems 4.4, 4.5 y 4.7; esas pruebas solo deben ejecutarse con cuentas y datos exclusivos de prueba.

## Decisiones tomadas

- Se usa `workflow_dispatch` para seleccionar explícitamente el despliegue y su versión, en vez de asumir que una URL o rama corresponde al build a validar.
- Se reutiliza el smoke test existente `npm run test:vercel`, que toma la URL de `LARUTICA_TEST_URL` y no modifica datos.
- El workflow requiere HTTPS, usa `contents: read` y fija por SHA las Actions externas.
- Los artefactos se publican con condición `always()` para conservar la evidencia aunque fallen health, instalación o smoke.

## Resultados

El workflow y la documentación quedaron preparados. No se afirma que se haya ejecutado contra Vercel ni contra otro despliegue; falta una ejecución manual que aporte URL, `deployed_commit` y artefactos de resultado.

## Limitaciones y alcance excluido

- El smoke test cubre navegación pública y no sustituye E2E del ítem 4.4, comprobaciones de autorización ni DAST con ZAP.
- E2E del ítem 4.4, autorización y ZAP dependen de los ítems 4.4, 4.5 y 4.7, respectivamente; solo deben ejecutarse usando cuentas y datos exclusivos de prueba.
- No se automatizan reservas, pagos, correos, creación de cuentas ni operaciones que modifiquen datos reales.
- Cada resultado debe asociarse al `deployed_commit` informado y a la URL HTTPS efectivamente validada; ambos quedan registrados en los artefactos.
